# Deep annotation brief — standing rules

Template for every deep per-sample annotation pass (R2026.18 deep shards, R2026.21 new-sample shards, R2026.23 subject pass).
The full brief used for a pass is kept with the pass's handoff files; the rules below are binding for every future pass.

SUBJECT RULE (standing rule for every annotation pass from R2026.23 on — the owner's decision):
 * A subject_id read from a source (BioSample host_subject_id / subject / patient / individual / participant / donor keys, sample-name tokens decoded by two agreeing replicates, a supplementary-table participant column) always wins. Determined_by as in the deep annotation; confidence 0.85 attribute, 0.7 decoded name, 0.85/0.8/0.75 paper tables.
 * GENERATED unique subject_id: when the sources show that every sequenced gut sample of the project comes from a different person (cross-sectional: one stool sample per participant), emit subject_id = the sample_key for each of the project's gut samples (body_site_class primary or unknown), with field_value 'one sample per subject', value_normalized = the sample_key, evidence_source 'design.one_sample_per_subject:<abstract|fulltext|description|archive>', evidence_quote = the verbatim design statement (<= 25 words), parse_note 'generated: one sample per subject (<basis>)', determined_by 'gut_subject_unique_v1', scope 'sample', route R3 when the evidence is the paper full text, R4 for an abstract or the archive description, R1 when the evidence is the archive records themselves (see basis c). Acceptable bases, strongest first:
   (a) an explicit statement: 'a single stool sample was collected from each participant', 'cross-sectional', 'one sample per subject' — confidence 0.75 (full text) / 0.65 (abstract, description);
   (b) a stated participant count equal to the project's catalog gut-sample count (e.g. '151 individuals' and 151 samples), with no statement of repeated / longitudinal / follow-up / pre-post / multiple time points sampling — confidence 0.7 (full text) / 0.6 (abstract);
   (c) archive structure only: every sample has a distinct value of a person-level attribute (age + sex + other host fields all present and the combinations never repeat) AND the description gives no sign of repeated sampling — confidence 0.55, route R1, evidence_source 'design.one_sample_per_subject:archive'.
 * NEVER generate when: the design is longitudinal / time series / repeated / pre-post / intervention with before-after sampling / multiple visits; timepoint labels differ within the project; sample names share stems with visit / day / week tokens; the participant count is smaller than the sample count; the project has technical replicates, multiple libraries per sample, pooled or split BioSamples (sample_unit = run); mother–infant designs where the same infant is sampled repeatedly; or the replicates disagree. For non-gut samples of the project (oral, milk, skin, ...) never generate (the same person may have given a stool sample). A project that is a member of a study group (study_group_id) counts its participants across the group.
 * Two independent reasoning-model replicates (host.llm, model=host.reasoning_model()) decide the design per project (one_sample_per_subject | multiple_samples_per_subject | unclear) from the evidence block; generate only when both say one_sample_per_subject AND the deterministic checks above pass (count match where a count is stated; no within-project timepoint variation; no repeated name stems).

Outputs of a pass are validated and staged with `scripts/integrate_deep.py --in-dir <shards> [--corrections config/deep_corrections.csv]`
into `data/inputs/gut/deep/`; generated subject ids are recognisable by `determined_by = gut_subject_unique_v1` and
`parse_note` starting with `generated:`.
