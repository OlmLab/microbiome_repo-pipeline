## 1.23.0 — 2026-10-21 (release R2026.28, external review fixes)
* **Curated supplementary tables** (`config/curated_supp_tables.yaml`, applied by `scripts/apply_curated_supp_tables.py` as data-quality corrections): a reviewed column mapping replaces the automatic reading for three projects.
  * PRJEB51728: subject ids now come from the meta-analysis Table S2 `subject_id` column (PMC11929092), joined on the sample alias; the automatic pass had taken run accessions from Table S9 `sequence_id`. 606 samples have a subject id; the 269 samples not in Table S2 have none.
  * PRJEB49383: the Source Data workbook of PMC9519454 gives patient number, day of life, antibiotics in the last 7 days, probiotic exposure, feeding and probiotic cohort (Infloran / Labinic / none) for 1,216 samples. The automatic pass had read the workbook but joined nothing: its sample ids carry a lane suffix (`NEW1016.S138.L005`) that the archive alias (`NEW1016`) does not.
  * PRJNA898628: Table S2 of the 2023 paper (PMC10192547; 32 columns, all 220 samples, keyed on run accession) gives the intervention group of every sample (antibiotics, antibiotics + probiotics, no treatment, term control), gestational age, birth weight, delivery, feeding, maternal antibiotics and NEC. Its supplement had failed to download (Europe PMC 503) and was never retried from PubMed Central because the project already had other tables.
* **Subject ids from sample columns are rejected everywhere.** A subject id taken from a column named sample / sample_id / sequence_id / run / BioSample / accession / library / family_id / study_id / manifest / barcode, or whose value is itself a run or sample accession, is dropped (ids minted on purpose for one-sample-per-person designs are kept).
* **CHILD (PRJNA838575) is flagged as restricted metadata** (`config/metadata_access_manual.csv`, new column `metadata_access_how`): the participant data are held under restricted access by the CHILD Cohort Study.
