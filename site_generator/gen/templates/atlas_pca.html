Method

Sandpiper 2.0.0 GTDB R232 profiles of every profiled run of the catalog (gut_sandpiper_sample_genus.parquet), summed over a sample's runs and normalised by the sample's root coverage. Samples with root coverage ≥ {{ method.root_min|default('2') }} genome equivalents enter the matrix; genera present at ≥ 0.1 % relative abundance in at least {{ method.prevalence_pct|default('1') }} % of these samples are kept ({{ n_genera|fmt if n_genera else '—' }} genera), re-closed to 1, zeros replaced by a multiplicative pseudocount of {{ method.pseudocount|default('1e-5') }}, log-transformed and centred per sample (CLR), then columns centred and decomposed by randomised SVD (5 components). Only the retained genera (not the unassigned remainder) enter the composition. Points are scores; loadings above are genus weights per component. Nearby points have similar genus compositions; distance is not a calibrated ecological metric — see Methods.

Data layout under data/atlas/: pca_points.bin ({{ sizes['pca_points.bin']|numint }} bytes) = little-endian Float32[n_points × n_pcs], row-major, point i component j at i·n_pcs+j; pca_codes.bin ({{ sizes['pca_codes.bin']|numint }} bytes) = one categorical column per field in the order {{ field_names|join(', ') }}, each Uint16 (study) or Uint8 (others) × n_points at the byte offset given in pca_meta.json → fields[k].offset; codes index fields[k].labels, whose last two entries are always other and (no value); pca_meta.json ({{ sizes['pca_meta.json']|numint }} bytes) carries the sample keys in point order (newline-joined), explained variance, loadings and study titles.
