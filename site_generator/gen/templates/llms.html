How the search works

  1. Start from a ready-made selection. Small files list the projects for one intervention, health condition or age group:
    • by intervention: {% for c, u in index.endpoints.by_intervention.items() %}{{ c }}{% if not loop.last %} · {% endif %}{% endfor %}
    • by age: {% for c, u in index.endpoints.by_age.items() %}{{ c }}{% if not loop.last %} · {% endif %}{% endfor %}
    • by health condition (one file per code in api/vocabularies.json): {% for c, u in index.endpoints.by_condition.items() %}{{ c }}{% if not loop.last %} · {% endif %}{% endfor %}
  2. Combine. Every project record has the same keys — e.g. take by-intervention/probiotic.json and keep projects whose health_conditions include crohns_disease: that is "Crohn's + probiotic".
  3. Open the samples. api/samples/<ACCESSION>.csv lists every sample with its arm (intervention: probiotic / placebo / no_intervention …), condition, age, country and sequencing depth.

The same filters are on the Projects (health condition × intervention × design × "treated & control arms") and Samples.

MCP server

An assistant that speaks the Model Context Protocol can query one release on your own machine instead of reading files from this site. {{ site.mcp_repo_name }} (the Python package is called microbiome-repo-mcp) is a small Python package that reads the unpacked data package with DuckDB and answers six kinds of question: find projects, filter samples, summarise a condition, prevalence of a taxon per body site, how to cite, and the coded values a filter accepts. It is pinned to one release, downloads nothing and writes nothing; every answer names the release it came from. Installation and the list of tools are in its README.
